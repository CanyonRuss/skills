# GTD Triage

The work is taking a list of undefined items and defining each one until it's settled where it belongs, with **GTD's Clarify and Organize**. You propose; the person you're working with decides.

**Claim only what's in evidence.** Evidence is the item's own words, what the record shows, and the context the person has provided. Every part of a proposal rests on it: what the item refers to, its next action, its date or urgency, its owner, its project and its place in it, its link to another item.

## The list

Work from the list the session already has, wherever it lives. When items have only come up in conversation, write each one down as it was provided, wherever the session keeps its working notes. Work out what each one is, including whether it repeats another, when you reach it in a batch. Add anything that comes up partway through to the end of the list, for a later batch.

## Clarify and organize

Ask GTD's clarifying questions of each item until you can give it a GTD disposition. Where a disposition needs something the evidence doesn't supply, put the question that would supply it to the person, in that item's place in the batch; a question whose answer wouldn't change the disposition can be left unanswered. If an item is a two-minute task, recommend that the person does it now or approves it for you to do. When an item is an outcome that takes more than one action, confirm the project and determine if it is already tracked. If it's not, then propose that its next action is planning. An item that belongs to an existing project gets tracked with the project's other tasks.

## The batch

Process the list ten items at a time. Fill each batch from the list with the items the evidence shows are time-sensitive first and related items together, and take it through these steps before starting the next.

1. **Prepare.** Re-read the sources to see what's still open and what's been added. For each item, look up what already exists that bears on it: a matching item or project, its last activity, a likely duplicate, anything waiting on someone, so that a match becomes an update or a move, where the source allows it, instead of a new item. Clarify each item.
2. **Propose** the batch as a numbered list. Suggest a disposition for each item, with the information the person needs to decide on it and a source for anything that isn't in the item's own words. Propose any potential duplicates, and keep two distinct actions as two items. An item with outstanding questions should be readdressed until it can be closed.
3. **Act** on the whole answered batch. Use any skills that may be needed for a destination. Report in one line what landed, counted by disposition, adding how many items remain open when any do.
4. **Close** each processed item at every source it came from, where the source supports it. Any item not fully processed, for whatever reason, stays open in its source.

## Stopping and handing off

Work to any timeframe the person gives, and stop at the end of a batch. Planning a project, reviewing the system and fixing how the workflow runs are separate work: when one comes up, propose a session of its own for it, note it for later, or hand it back to the session you're working in.
