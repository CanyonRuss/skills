---
name: handback-report
description: >
  Write a handback report: the status the user sends to the session
  that prompted this work, including where the work stands and what
  came of it. Use when the user asks for a handback, a report back, or
  what to paste back. Companion to kickoff-prompt: reports on work it
  sent out. Not handoff-doc, which is for whoever continues the work,
  and not a status summary for the user.
---

Write a status report from this session to the session that prompted the work. A good one shows the receiver, from the report alone, where that work stands and what came of it. Keep it short, and emit it as a single fenced code block in chat.

Include only what would change how the receiver understands the work:

- **Which work** — just enough for the receiver to recognize the work, without restating it.
- **Status** — where the work stands: done, in progress, blocked or stopped, and why, if it fell short.
- **Conclusions** — what came of the work: what it found, decided, produced or changed. A reference can go alongside a conclusion but never stand in for one.
- **Standing** — what this session verified, and what it's passing on unchecked.
- **Open** — what's unresolved.
- **Waiting on** — what the work can't move without.
- **Other info** — anything that came up that the receiver would benefit from knowing.

Leave out what mattered only in getting here: decisions this session made for itself, paths it tried, how it reached its conclusions. Use no shorthand or labels that only make sense in this session. Address nothing to the receiver, and give it no next steps.

Redact secrets and personal data — say where they live instead.
